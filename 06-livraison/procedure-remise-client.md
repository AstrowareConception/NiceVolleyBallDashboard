# Procédure de remise client

Ce document sert à organiser le passage de relais au Nice Volley Ball.

## 1. Éléments à remettre

- URL de l'application ;
- comptes utilisateurs nécessaires ;
- documentation utilisateur ;
- documentation d'exploitation ;
- procédure de déploiement ;
- procédure de sauvegarde/restauration ;
- PV de recette ;
- backlog restant ;
- liste des réserves ;
- schéma d'architecture ;
- règles RGPD retenues ou à valider.

## 2. Accès et propriété

| Élément | Propriétaire attendu | Statut |
|---|---|---|
| VPS | Club ou compte transférable | À compléter |
| Domaine / sous-domaine | Club | À compléter |
| Clés Brevo | Club | À compléter |
| Clés Weezevent | Club | À compléter |
| Dépôt applicatif | À définir | À compléter |
| Comptes administrateurs | Club | À compléter |

Les comptes personnels étudiants ne doivent pas être indispensables au fonctionnement durable du service.

## 3. Démonstration de remise

Scénario minimal :

1. se connecter ;
2. vérifier le dashboard ;
3. lancer ou présenter une synchronisation Weezevent ;
4. sélectionner un événement ;
5. exporter les contacts ;
6. afficher les nouveaux spectateurs ;
7. vérifier le consentement ;
8. synchroniser ou préparer une liste Brevo ;
9. consulter les logs ;
10. expliquer sauvegarde et restauration.

## 4. Réserves

Lister les limites connues, par exemple : données Weezevent non disponibles, règle RGPD à confirmer, HTTPS non activé, pipeline partiel, restauration non testée.

## 5. Validation

Le client doit pouvoir indiquer :

- validé sans réserve ;
- validé avec réserves ;
- non validé en l'état.

La décision doit être reportée dans le [PV de recette](pv-recette.md).
