# Valorisation BTS SIO

Cette section sert de repère pour transformer le projet en preuves exploitables dans le portfolio et le tableau de synthèse.

## Principe

Le projet est collectif, mais les preuves doivent permettre d'identifier la contribution personnelle de chaque étudiant.

Un étudiant ne doit pas revendiquer une compétence uniquement parce que le groupe l'a travaillée. Il doit pouvoir expliquer :

- ce qu'il a fait ;
- comment il l'a fait ;
- avec quels outils ;
- quel résultat il a obtenu ;
- quelle preuve le démontre ;
- ce qu'il a appris ou améliorerait.

## Preuves possibles

- captures d'écran légendées ;
- commits Git ;
- tickets ou tâches de backlog ;
- schémas ;
- MCD/MLD ;
- scripts ;
- documentation ;
- procédures ;
- rapport de test ;
- compte rendu de recette ;
- support de présentation ;
- bilan personnel.

## Compétences Bloc 1 particulièrement mobilisables

- gérer le patrimoine informatique ;
- répondre aux incidents et demandes d'évolution ;
- développer la présence en ligne de l'organisation ;
- travailler en mode projet ;
- mettre à disposition un service informatique ;
- organiser son développement professionnel.

## Attention

Certaines compétences ne doivent être conservées que si elles sont réellement démontrées. Par exemple, le déploiement n'est pleinement défendable que si un environnement cible existe, que le service fonctionne dessus et que la procédure est documentée.

## Travail étudiant recommandé

Chaque étudiant doit constituer une fiche personnelle avec :

1. rôle dans le projet ;
2. contributions principales ;
3. compétences visées ;
4. preuves associées ;
5. limites ;
6. plan de progression pour la suite.
