# Semaine 2 — Finalisation et livraison

## Objectif de la semaine

La deuxième semaine intensive vise la livraison du produit au client. Il s'agit de terminer proprement ce qui a été commencé en juin, de prendre en compte les remarques d'Alexandre, de stabiliser le dashboard, de le déployer et de produire les documents nécessaires à son exploitation.

## Point de départ

Le projet dispose déjà d'un MVP validé : récupération d'événements Weezevent, traitement de données, identification de nouveaux spectateurs et envoi d'une liste vers Brevo.

La semaine 2 doit donc se concentrer sur :

- la reprise du besoin ;
- les évolutions fonctionnelles ;
- le RGPD ;
- la livraison technique ;
- les tests ;
- la documentation ;
- la recette client.

## Déroulé recommandé

### Lundi matin — reprise collective

Toute la classe reprend :

- le MVP de juin ;
- le contexte client ;
- les retours d'Alexandre ;
- le périmètre de livraison ;
- les priorités ;
- les rôles.

La production principale de cette matinée est le micro-cahier des charges V2.

- évolution MCD/MLD ;
- priorisation ;
- préparation du VPS ;
- démarrage des tests.

### Mercredi — intégration et préproduction

- intégration front/back/base ;
- déploiement ou préproduction ;

- correction des bugs bloquants.

- sauvegardes ;
