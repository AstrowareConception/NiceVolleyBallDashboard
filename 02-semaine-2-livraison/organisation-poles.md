# Organisation par pôles — semaine 2

## Vue d'ensemble

La semaine 2 est organisée autour de cinq pôles. Certains pôles sont permanents, d'autres sont temporaires.

## Pôle gestion de projet

Effectif : 2 étudiants, idéalement 1 SLAM et 1 SISR.

Responsabilités :

- animer les points quotidiens ;
- maintenir le backlog ;
- mettre à jour le MoSCoW ;
- suivre le WBS, le RACI et le Gantt ;
- identifier les risques ;
- organiser les arbitrages ;
- préparer la démo finale ;
- centraliser les livrables.

Livrables :

- micro-cahier des charges V2 ;
- backlog priorisé ;
- RACI ;
- suivi d'avancement ;
- compte rendu quotidien ;
- bilan final.

## Pôle migration / cadrage fonctionnel / données

Effectif : 2 étudiants au début de semaine.

Ce pôle est temporaire. Il travaille surtout lundi et mardi matin, puis ses membres peuvent rejoindre développement, test ou documentation.

Responsabilités :

- analyser le prototype V1 ;
- identifier les impacts des retours client ;
- mettre à jour MCD/MLD ;
- définir les migrations SQL ;
- formaliser les règles de gestion ;
- produire le mapping besoins / écrans / routes API ;
- préparer les cas de test associés.

Livrables :

- document d'évolution V1 vers V2 ;
- MCD/MLD mis à jour ;
- migrations SQL ;
- règles de gestion ;
- impacts fonctionnels.

## Pôle développement

Effectif : 2 à 3 étudiants SLAM.

Responsabilités :

- corriger et finaliser le backend PHP/Slim ;
- finaliser le frontend HTML/Tailwind/JavaScript ;
- intégrer les nouvelles règles métier ;
- gérer export événement, invitations, consentement, Brevo ;
- corriger les anomalies remontées par le pôle test ;
- documenter les routes.

Livrables :

- code applicatif stable ;
- routes API finalisées ;
- écrans finalisés ;
- changelog ;
- documentation technique applicative.

## Pôle déploiement

Effectif : 2 à 3 étudiants, idéalement 2 SISR et 1 SLAM.

Responsabilités :

- choisir ou louer le VPS avec le client ;
- configurer SSH ;
- installer Docker ;
- préparer Docker Compose production ;
- configurer reverse proxy et HTTPS ;
- gérer les secrets ;
- préparer le pipeline de déploiement ;
- mettre en place sauvegarde/restauration ;
- documenter l'exploitation.

Livrables :

- VPS ou environnement cible configuré ;
- pipeline de déploiement ;
- procédure de déploiement ;
- procédure sauvegarde/restauration ;
- documentation d'exploitation ;
- checklist sécurité.

## Pôle test / recette / documentation

Effectif : 2 étudiants.

Responsabilités :

- définir les tests end-to-end ;
- préparer les jeux d'essai ;
- tester les parcours ;
- remonter les anomalies ;
- vérifier les corrections ;
- rédiger la documentation utilisateur ;
- préparer la recette client.

Livrables :

- plan de test ;
- rapport de test ;
- suivi des anomalies ;
- guide utilisateur ;
- support de recette ;
- compte rendu de validation.

## Règle de fonctionnement

Chaque pôle doit terminer chaque journée avec :

- ce qui a été fait ;
- ce qui reste à faire ;
- les blocages ;
- les décisions nécessaires ;
- les preuves produites.
